# Демо-данные для совместных подборок

Команда создаёт безопасные локальные данные для Postman и ручного тестирования:

```powershell
docker compose exec backend python manage.py seed_collaborations_demo
```

Она идемпотентна: повторный запуск не дублирует пользователей, котиков,
подборки, роли и заявки. Чтобы пересоздать только тестовые сущности команды,
используйте:

```powershell
docker compose exec backend python manage.py seed_collaborations_demo --reset
```

## Учётные записи

Пароль всех тестовых пользователей: `Demo-Collaboration-42!`.

| Пользователь | Роль в обеих подборках | Котики |
|---|---|---:|
| `demo_owner` | Владелец | 5 |
| `demo_editor` | Редактор | 5 |
| `demo_viewer` | Читатель | 5 |
| `demo_guest_one` | Нет роли | 1 |
| `demo_guest_two` | Нет роли | 1 |

Создаются две подборки:

1. «Коты из приютов» — пять котиков владельца.
2. «Коты-путешественники» — пять котиков редактора.

У каждого гостя есть собственный котик и ожидающая заявка (`pending`) в одну
из подборок. Поэтому сразу можно проверить принятие или отклонение заявок,
доступ читателя, добавление котика редактором и запрет действий пользователя
без роли.

После запуска команда выводит фактические идентификаторы подборок. Их нужно
подставить в переменную `collectionId` Postman-коллекции. JWT для любого
пользователя получается через `POST /auth/jwt/create/`.

В текущем локальном запуске подготовлены значения по умолчанию для Postman:
`collectionId=1`, `editorUserId=2`, `ownerCatId=1`, `outsiderCatId=16` и
`proposalId=1`. После `--reset` эти значения могут измениться; используйте
вывод команды seed, чтобы обновить переменные.

Эти данные предназначены только для локальной разработки и демонстрации, не
для production.
